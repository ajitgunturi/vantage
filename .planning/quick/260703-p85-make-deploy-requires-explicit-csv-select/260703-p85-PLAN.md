<objective>
Make streamer CSV selection mandatory and intentional in the `make deploy` path. Today
`build/streamer.Dockerfile` silently globs `dcgm_metrics_*.csv` and falls back to the committed
fixture — so a deploy can ship demo data without the operator noticing. This plan makes `make deploy`
require an explicit `CSV=<path>` (or an interactive prompt on a TTY, or a loud failure when scripted),
validate it, and bake exactly that file. The fixture fallback survives only on the dev/test targets
(`make docker`, `make docker-streamer`) and compose/e2e flows.

Purpose: an external evaluator on a fresh clone must consciously choose which telemetry CSV runs in the
cluster — never get the fixture by accident.
Output: updated Makefile, streamer.Dockerfile, .dockerignore/.gitignore notes, and README docs.
</objective>

  <action>
Rework the deploy path so it demands an explicit CSV and bakes exactly that file, while leaving the
dev/test build path (fixture fallback) intact.

**build/streamer.Dockerfile** — replace the current bake block (lines ~18-31). Declare a build arg in
the builder stage just before the bake step: `ARG DEPLOY_CSV=` (empty default). Rewrite the bake RUN so
that when `DEPLOY_CSV` is non-empty it copies that context-relative path to `/out/data/dcgm_metrics.csv`
(echo which file it is baking); when empty it keeps the existing behavior exactly — glob
`dcgm_metrics_*.csv` first, else copy `build/fixture/dcgm_metrics.csv`. The staged deploy file arrives
via the existing `COPY . .` (it lives inside the build context), so no new COPY line is needed. Do NOT
use build-arg substitution inside a COPY source (unsupported) — resolve the path in the RUN shell only.
Update the head comment above the bake step to document the DEPLOY_CSV deploy path alongside the
fixture fallback.

**Makefile** — convert `deploy` from a bare prereq chain into a recipe target (keep `check-env` as the
only prerequisite; drop `docker kind-load helm-install` from the prereq list — the recipe invokes them
via `$(MAKE)` so ordering + CSV plumbing are controlled). The recipe, run under a single shell block:
  1. Read `csv := $(CSV)`. If empty and stdin is a TTY (`[ -t 0 ]`), prompt: print
     "Path to DCGM telemetry CSV to bake into the streamer image: " and `read -r csv`.
  2. If empty and NOT a TTY, print an error + usage (`Usage: make deploy CSV=/path/to/your.csv` and a
     line noting deploy never falls back to the demo fixture) and `exit 1`.
  3. If still empty (TTY user hit enter), error and `exit 1`.
  4. Validate: if `[ ! -f "$$csv" ] || [ ! -r "$$csv" ]`, print `ERROR: CSV not found or not readable: <path>`
     and `exit 1`.
  5. Stage: `mkdir -p build/.deploy && cp "$$csv" build/.deploy/dcgm_metrics.csv`; echo the chosen path.
  6. Run `$(MAKE) docker DEPLOY_CSV=build/.deploy/dcgm_metrics.csv && $(MAKE) kind-load && $(MAKE) helm-install`;
     capture status; always `rm -rf build/.deploy` (cleanup on success AND failure); `exit $$status`.
Update the deploy `##` help text to mention `CSV=<path>` and the prompt/fail behavior, matching existing
Makefile help style.

Add an explicit `docker-streamer` target (explicit rules override the `docker-%` pattern rule, and it is
still picked up as a prereq of `docker` via `$(addprefix docker-,$(DOCKER_IMAGES))`). It builds
`build/streamer.Dockerfile` and, when `$(DEPLOY_CSV)` is set, passes `--build-arg DEPLOY_CSV=$(DEPLOY_CSV)`;
when unset, passes no build arg so the fixture fallback path runs. Add `docker-streamer` to the `.PHONY`
line. Leave `docker`, `docker-%`, `kind-load`, `helm-install`, and all other targets unchanged so
`make docker` (dev) and `make docker-streamer` (dev) keep fixture-fallback behavior.

**.gitignore** — add `build/.deploy/` so the transient staged CSV is never committed.

**.dockerignore** — update the existing `dcgm_metrics_*.csv` note comment to also mention that
`build/.deploy/` must remain in the context for the deploy bake (do not add an exclude for it).
