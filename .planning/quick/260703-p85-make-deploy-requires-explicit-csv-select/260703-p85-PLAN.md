<objective>
Make streamer CSV selection mandatory and intentional in the `make deploy` path, and eliminate the
redundant committed fixture. Today `build/streamer.Dockerfile` silently globs `dcgm_metrics_*.csv` and
falls back to a committed 12-row fixture (`build/fixture/dcgm_metrics.csv`) — a deploy can ship demo
data without the operator noticing, and the repo carries two copies of test CSVs.

Owner directive (2026-07-03, supersedes the earlier "keep fixture fallback for dev/test targets"
requirement): `build/fixture/dcgm_metrics.csv` is NOT needed — delete it. Tests keep using
`testdata/fixture.csv` (the single test fixture). `make deploy` must ask the user for the CSV path
(or take `CSV=<path>`) and use exactly that path in the docker build. No silent fallback anywhere in
the image build.

Verified-safe: no test, script, or compose file reads `build/fixture/` — only the Dockerfile fallback,
a `.dockerignore` comment, and `docs/streamer.readme.md` reference it. `docker-compose.full.yml` uses
`image: vantage/streamer:dev` (not `build:`) and mounts `./testdata/fixture.csv` over
`/data/dcgm_metrics.csv` at runtime, so a CSV-less image works for all dev/test flows.

Purpose: an external evaluator on a fresh clone must consciously choose which telemetry CSV runs in the
cluster; the repo keeps exactly one test fixture (`testdata/fixture.csv`).
Output: updated Makefile, streamer.Dockerfile, deleted build/fixture/, doc updates.
</objective>

**Delete `build/fixture/dcgm_metrics.csv`** (and the now-empty `build/fixture/` directory) via `git rm`.

**Makefile** — convert `deploy` from a bare prereq chain into a recipe target (keep `check-env` as the
only prerequisite; drop `docker kind-load helm-install` from the prereq list — the recipe invokes them
via `$(MAKE)` so ordering + CSV plumbing are controlled). The recipe, run under a single shell block:
  1. Read `csv := $(CSV)`. If empty and stdin is a TTY (`[ -t 0 ]`), prompt: print
     "Path to DCGM telemetry CSV to bake into the streamer image: " and `read -r csv`.
  2. If empty and NOT a TTY, print an error + usage (`Usage: make deploy CSV=/path/to/your.csv` and a
     line noting the streamer image bakes no CSV unless one is supplied) and `exit 1`.
  3. If still empty (TTY user hit enter), error and `exit 1`.
  4. Validate: if `[ ! -f "$$csv" ] || [ ! -r "$$csv" ]`, print `ERROR: CSV not found or not readable: <path>`
     and `exit 1`.
  5. Stage: `mkdir -p build/.deploy && cp "$$csv" build/.deploy/dcgm_metrics.csv`; echo the chosen path.
     (Staging into the build context handles CSVs living anywhere on disk.)
  6. Run `$(MAKE) docker DEPLOY_CSV=build/.deploy/dcgm_metrics.csv && $(MAKE) kind-load && $(MAKE) helm-install`;
     capture status; always `rm -rf build/.deploy` (cleanup on success AND failure); `exit $$status`.
Update the deploy `##` help text to mention `CSV=<path>` and the prompt/fail behavior, matching existing
Makefile help style.

Add an explicit `docker-streamer` target (explicit rules override the `docker-%` pattern rule, and it is
still picked up as a prereq of `docker` via `$(addprefix docker-,$(DOCKER_IMAGES))`). It builds
`build/streamer.Dockerfile` and, when `$(DEPLOY_CSV)` is set, passes `--build-arg DEPLOY_CSV=$(DEPLOY_CSV)`;
when unset, passes no build arg (CSV-less image). Add `docker-streamer` to the `.PHONY` line. Leave
`docker`, `docker-%`, `kind-load`, `helm-install`, and all other targets unchanged.

**.gitignore** — add `build/.deploy/` so the transient staged CSV is never committed. Leave the
existing `dcgm_metrics_*.csv` line as-is (the real export stays local-only).

**.dockerignore** — replace the stale NOTE about baking `dcgm_metrics_*.csv` (fallback is gone). Add

build context (patterns anchor at context root, so `build/.deploy/dcgm_metrics.csv` is NOT matched —
keep a short comment saying build/.deploy must remain in the context for the deploy bake).

**docs/streamer.readme.md** — update line ~19 (mentions the committed fixture fallback) to describe the
