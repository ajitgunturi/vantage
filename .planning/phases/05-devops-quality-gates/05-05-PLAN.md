<objective>
Break the Helm pre-install-hook deadlock that hangs `make deploy` and blocks all of Phase 5 UAT
(Test 1 failed, Test 2 blocked). `deployments/templates/migrate-job.yaml` is a
`helm.sh/hook: pre-install,pre-upgrade` Job whose `wait-for-postgres` init container loops on
`nc -z vantage-postgresql 5432`, but Helm runs pre-install hooks to completion BEFORE creating any
regular release resource — including the Bitnami postgresql Service the init container waits on.
Circular wait → silent hang → 5m timeout failure. The pre-upgrade path deadlocks identically.

Fix: move the migration Job to a `post-install,post-upgrade` hook so Postgres exists before the
hook runs, add loud bounded-failure guards (Job `activeDeadlineSeconds` + explicit helm
`--timeout`), clear the stranded release, and re-prove the full E2E path.

Purpose: Restore the OPS-02 (helm install brings all pods Running) and OPS-03 (targeted
independent upgrade) success criteria so the phase can be verified and soaked.
Output: Corrected migration hook, loud-failure Makefile deploy, green `make smoke-05` on a clean
kind cluster.

Deviation note: This deliberately corrects locked decision D-09 ("pre-install/pre-upgrade hook").
The hook PHASE moves from pre to post — the diagnosis (reviewed by the owner in 05-UAT.md /
.planning/debug/helm-install-hang.md) explicitly offered post-install/post-upgrade as an approved
fix direction. D-09's intent is preserved: a dedicated migration Job still runs once per release
operation, and Helm still blocks until it completes. Services already tolerate the brief
post-Postgres / pre-migration window (collector self-migrates via db.Migrate at startup and retries
through crashloop; gateway returns 500, not crash, until the schema exists), so no service is
harmed by migration completing shortly after service pods roll.
</objective>

    `helm upgrade --reuse-values --set mq.image.tag=dev`.

    `restartPolicy: Never`.

    `template`, NOT inside the pod spec) so a migration that cannot complete fails the Job — and
    therefore the hook — within 2 minutes instead of hanging to Helm's default 5m. Update the
    init-container comment that currently references "Pitfall 7" to state the corrected ordering
    (Postgres is a regular resource created before this post-install hook, so the wait resolves).
