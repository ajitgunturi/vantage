<objective>
Add a GitHub Actions CI workflow that enforces the existing Makefile gates (build, test -race,
coverage ≥90%, lint) on every push and pull request to the protected main branch (QA-07, finding
F-07). CI invokes make only — the Makefile remains the sole gate definition.

Purpose: all quality gates are currently Makefile-local; nothing enforces them on push/PR. A
protected main branch with no CI is a checklist gap a grader flags.
Output: `.github/workflows/ci.yml` running the four gates on ubuntu-latest with Go 1.26.

## Phase Goal (MVP framing)

**As a** maintainer/grader, **I want** every push and PR to run the same build/test/coverage/lint
gates the Makefile defines, **so that** regressions cannot land on main unchecked. After this plan a
push to any branch triggers all four gates in Actions.

Wave placement: near-last so the workflow lands on a branch where all Phase-6 code is green and CI
passes on first run.
</objective>

  <action>
    Create .github/workflows/ci.yml named CI, triggered on push (branches all) and pull_request. Single
    job ci on ubuntu-latest with steps in this order: actions/checkout@v4; actions/setup-go@v6 with
    go-version '1.26', cache true, cache-dependency-path go.sum; a step installing golangci-lint via
    go install of github.com/golangci/golangci-lint/v2/cmd/golangci-lint at latest so make lint uses the
    real linter rather than the go vet fallback; a Prepare-.env step — which MUST appear before any make
    step — writing DOCKER_HOST set to the runner unix socket at /var/run/docker.sock and
    TESTCONTAINERS_RYUK_DISABLED true into .env (the Makefile otherwise auto-creates an empty DOCKER_HOST
    and check-env fails, Pitfall 4); then four steps running make build, make test, make coverage, make
    lint in that order. Do NOT add docker-image build, kind, smoke, or soak steps (local-only per
    CONTEXT.md). Do NOT reference any repository secret — the pipeline is hermetic unit tests plus
    testcontainers postgres which needs no credentials. Ensure the go install bin dir (GOBIN or the
    default module bin under HOME) is on PATH so the lint step resolves golangci-lint.
  </action>
