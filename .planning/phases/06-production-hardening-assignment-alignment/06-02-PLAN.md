<objective>
Add offset/limit pagination with a metadata envelope to the telemetry endpoint (API-05, finding
F-06) and expose `/healthz` + `/readyz` on the gateway (OBS-01, finding F-02), regenerating the
OpenAPI spec from swag annotations.

Purpose: "Return all telemetry for a GPU" grows without bound under a looping streamer; the current
hard row-cap truncates with no continuation. Pagination gives clients a real cursor. Health
endpoints let Kubernetes detect a gateway with a dead DB pool.
Output: `TelemetryPage`/`PaginationMeta` response types, `db.Telemetry(..., limit, offset)`,
gateway `HealthzHandler`/`ReadyzHandler`, updated swagger spec.

## Phase Goal (MVP framing)

**As a** telemetry API client, **I want to** page through a GPU's telemetry with limit/offset and
know whether more rows exist, **so that** I can retrieve the full history without a truncating cap;
**and as an** operator, I want the gateway to report readiness so Kubernetes stops routing to it
when Postgres is unreachable.

Vertical slice order: (1) failing tests pin the pagination + health contract, (2) SQL + handler
push-down make paging real end-to-end, (3) health endpoints + swagger regen close the operability
and docs gaps. After Task 2 a client can actually page; after Task 3 Kubernetes can gate the pod.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → gateway HTTP API | Untrusted query params (limit, offset) cross here |
| gateway → PostgreSQL | Params flow into SQL; readiness probe pings the pool |
| Kubernetes kubelet → /healthz,/readyz | Operational probes; responses must not leak internals |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03 | Tampering | limit/offset → db.Telemetry SQL | high | mitigate | Bind limit/offset as `$N` pgx placeholders only; never string-concatenate into SQL (ASVS V5). Grep gate asserts no fmt/strconv into query text. |
| T-06-04 | Denial of Service | limit query param | medium | mitigate | Enforce ceiling at cfg.MaxRows (default 1000); reject limit<1 with 400; offset<0 rejected. Deep-offset cost accepted for assignment scope. |
| T-06-05 | Information Disclosure | /readyz, /healthz responses | medium | mitigate | Responses return only `{"status":"ok"}` or generic "not ready"; ReadyzHandler never echoes DSN, pg driver error, or version (ASVS V8). |
</threat_model>
